# 嵌套会话与任务协作

后续任务可先提议、由用户确认后独立启动或排入当前会话；输入框支持可关闭的下一步建议。详见 [后续任务与输入建议](FOLLOW-UPS.md)。

适用版本：DSH 0.2.1-rc.2。嵌套会话是 Agent 用来分工的独立工作对话，人数、任务分配和模型由 Agent 自己选择。

## 怎么使用

普通任务直接在原对话中描述，Agent 按需判断是否拆分；较小任务可能直接完成，不会为了显示进度而硬开几个子会话。

明确需要独立子会话协作时，在任意已有对话输入（不必先打开进度面板）：

```text
/collaborate 审查当前项目的 API、安全与界面问题，最后汇总改进优先级
```

这条命令只表达“本任务启用协作”，不会指定人数、模型或代替 Agent 创建固定数量的会话。Agent 先分析任务，查询已配置模型，再自行调用 start_session 分派；子会话的真实结果返回原对话，主 Agent 收集后汇总。

左侧原会话树直接展示父子关系，标题栏 **任务协作** 查看当前家族的模型、结果和停止操作。重复的全局 **协作进度** 入口和第二个任务输入框均已移除。**开启协作并回主会话** 是可选的模式切换，不会提交任务；自然语言完整交付或 `/collaborate 任务内容` 都不要求先点它。

一个任务家族只有一个主会话负责分工与汇总。子会话不能创建孙会话；需要更多人手时通过 `send_session_message` 向主会话请求，由主会话决定是否创建同级子任务。在子会话输入 `/collaborate 任务内容` 也会路由到所属主会话，不会把当前子会话变成第二个指挥者。无关联的普通对话使用该命令时，自身就是新的主会话。

| 操作 | 行为 |
|---|---|
| /collaborate on | 只开启当前任务家族协作，尚未提交任务；随后回主会话描述任务 |
| /collaborate off | 暂停新分工；保留已有会话和历史 |
| /collaborate auto | 恢复按需模式，较小任务可直接处理 |
| 查看结果 | 打开原生子会话阅读结果，可直接返回主会话 |
| 停止此任务 | 取消该子任务并清空待执行消息 |
| 停止所有子任务 | 暂停新分工并停止当前家族的全部子任务，保留历史 |
| 返回主会话 | 从子会话回到原任务 |

界面显示任务状态、实际使用的模型和 Agent 给出的简短分配理由。宿主重启后没有实际运行的旧任务会显示“等待继续”，不把历史 running 标记当作仍在执行的证据。

任务协作弹层按原生状态 Map 区分“需要介入 / 进行中 / 已完成”，保留父子树。等待回答、权限审批和方案确认优先于 running；停止的任务保持停止，不计作完成。这里的计数只统计当前任务的已加载子会话；原生侧栏仍使用宿主已有状态点，没有另设全局协作页或复制待答状态。

主会话的后台未读提醒只标为“有新进展”，不据此推断成功；子任务完成计数使用已有终态记录，避免把失败或用户停止误报为完成。

新分工只产生“主会话 → 直接子任务”两层。已有深层历史保持原关系，UI 仍递归展示并检查循环，不会迁移或删掉旧对话；“返回主会话”回到整个家族的根节点。

## 执行与边界

需要让当前 Agent 查阅其他工作区的本机会话时，先在 **任务协作 → 当前会话查阅本机历史** 开启，或输入 `/local-history on`，再用自然语言描述要找的历史。`list_recent_sessions` 返回最近的最多 20 个会话，排除归档、空白和原生 subagent；`read_local_session` 返回有界文本。已知归档会话 ID 时仍可显式只读查看历史，不会恢复执行。

这项授权只属于当前会话、仅本次宿主运行有效，不继承给子会话或 fork，彻底退出/重启后自动关闭。`/local-history off` 可立即撤销，在途读取也会再次核对授权；关闭后重新开启不能让先前的旧读取穿透。它不授予跨家族消息、停止或其他控制权限，也不改动原生已有的同工作区搜索规则。历史内容作为参考，不覆盖当前用户意图。

后台会话在当前界面打开期间完成时，会在右下角出现 **后台任务已完成**，点击 **查看结果** 打开对应原生会话。只提醒实际 completed 终态，不把失败、阻塞或用户停止当完成；停止/归档保护同样适用。首屏和重新开启提醒时不重放旧记录，同一回合不会重复提醒；界面最多保留三条。当前主区域会话完成不提醒，右侧会话仍按后台会话处理。

“任务协作”底部的 **后台完成通知** 可关闭或恢复，偏好保存在当前浏览器/桌面端的本地配置中。系统通知只在平台已有授权时尝试发送固定通用文案，不带任务标题或正文，也不主动弹出授权请求；Windows 勿扰及通知设置仍可能隐藏横幅。应用内提醒不依赖系统横幅。通知仅用于查看结果，不会向模型提交新任务。

在“任务协作”的主/子会话卡片点击 **并排查看**，可在原生右侧栏打开另一个会话；当前主区域保持不变。两侧均为原生 Conversation，各自保留草稿、权限、模型和消息目标。标签可关闭、重开及通过原生面板调整宽度；窄窗口由宿主决定是否全屏显示。重复打开同一目标复用标签，关闭显示不会停止后台任务。当前会话的并排按钮禁用，避免在同一窗口重复挂载同一个输入框。

会话头部“任务协作”中，每个主/子会话均可展开 **任务与回顾**：读取原生任务清单和最近三个已结束回合的回复摘要。即使原生问题卡替换输入区，也能在这里查看任务进展；展开时刷新，收起后停止读取。最多预览 40 项任务，完整清单在原生会话中；回顾沿用原生回复片段，不额外请求模型，也不等同于独立验收结论。

显式 `send_session_message` 使用原生 `followup`，排在接收方当前回合之后，保留发送会话身份；自动终态报告仍使用 `steer` 在主会话下一步汇总，且仅发送有界结果，不搬运子会话原始工具输出。发送和自动回报均在异步解析后再次检查发送方、接收方的停止和归档状态。

原生桌面“停止生成”保留待办队列但不重新唤醒任务；`stop_session` 明确取消并清空队列。原生用户取消信号即时阻止继续通信，只有后续明确的用户输入才解除停止状态；迟到的取消事件不能覆盖新输入，先前已被取消的输入也不能反过来解除新停止。

- start_session 复用原生 create/fork；fresh 只传完整 brief，fork 继承已完成轮次。不是伪装成子任务的消息列表。
- list_session_models 查询当前 provider/proxy 配置中的模型及已公开能力；工具要求 Agent 明确传入 provider/model。未配置模型在创建前被拒绝，不虚构价格、性能或可用性。
- 模型分配通过会话级 model/selection 和原生请求钩子生效；不会调用会保存全局默认值的模型切换操作。用户后来在子会话手动选模型仍然有效。
- 子会话继承父会话的原生权限预设和角色；无法安全继承的自定义权限明确拒绝。不会用新建独立会话提升权限。
- wait_for_sessions 等待实际执行并收集结果；完成/失败/阻塞通过真实终态回传去重。已人工停止的会话不得被自动结果重新唤醒。
- 家族通信使用原生 agent-message；用户通过协作命令发起的任务使用主会话的原生用户消息。路由前校验子会话和主会话的访问权限，保留家族权限与 RemoteAccess 校验。
- 并行改代码应先创建独立 worktree 并传 cwd，或使用既有 Agent Team 的 worktree 隔离；共享目录中不能同时改同一文件。
- `create_worktree` 会切换调用会话的目录；先固定交付目录和基准，每次回到交付目录再创建下一份，全部准备好再分派。结果先审阅整合后验收，详见 [并行写入与整合](WORKTREE-DELIVERY.md)。

验收命令（先在隔离 DSH_HOME 安装本仓库配置，设置本机 OPENAI_API_KEY）：

```powershell
rtk proxy node scripts/harness.mjs automatic-test --home .local/test-home
```

它会产生真实 proxy 请求：通过 /collaborate 提交合成的多部分审查任务，不规定子任务数量或模型；检查 Agent 自己调用模型目录与分工工具、实际子会话请求头中的模型、权限继承、最终汇总以及全局默认模型未变。脚本不把“工具存在”或手工调用创建 RPC 当作自动协作通过。

## 与 Claude 的关系

截图中的功能确实称为 nested sessions。它是独立会话的组织与执行层，不等同于 Team，也不能仅凭树形外观认定为 subagent。

- 普通 subagent：一次委派的 Agent 上下文；最新 [官方 subagent 文档](https://code.claude.com/docs/en/sub-agents#resume-subagents) 已允许 SendMessage 恢复/通信，不能再笼统说只能返回一次结果。
- [Agent Teams](https://code.claude.com/docs/en/agent-teams)：增加共享任务、成员协作及团队协议。
- [桌面多会话](https://code.claude.com/docs/en/desktop#work-across-sessions)及[跨会话消息](https://code.claude.com/docs/en/cross-session-messaging)：独立会话之间的读取、消息和管理能力。

本次只读取公开官方文档、[公开 CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md) 和本机安装包的离线静态内容。未启动 Claude 或 CLI，未附加进程、连接调试端口、读取私人会话/凭据，也未请求登录态接口。不复制 Claude 的源码，不连接它的本地 IPC。DSH 的实现使用自己的原生服务，可在没有 Claude 的电脑上安装。

离线调查的 Claude 产品元数据为 2.42304.2；SDK 依赖声明为 0.3.299，二者不等于 CLI 版本。安装包中观察到 `side_session`、`fork`、`hand_off`、`suggested_task` 等 lineage，fresh/fork 创建真实新会话，关系脱离和完成通知各有独立状态。没有读取截图条目的私人存储，因此不能断言每一条具体属于哪种 lineage。

## 验证和边界

### 全部会话状态

侧栏底部的 **会话状态** 打开跨工作区分组：需要介入、进行中、已完成，以及停止/未开始/状态不可用的其他会话。它直接打开原会话，不恢复旧的全局协作页面；任务分工、停止和结果管理仍在会话标题栏的“任务协作”中，原工作区父子树保持。

待回答、审批和计划审查优先于运行状态；“已完成”只表示原生回合以 completed 结束，不代表独立验收通过。错误和阻塞列入需要介入，用户停止不会冒充成功。归档、空白和原生 subagent 不列入这个普通会话列表。历史较多时每组先显示 20 项，可以继续展开。

打开时才按每批最多 20 项、一次一个请求读取原生状态，不调用模型，也不激活冷历史 Agent。关闭即取消读取并清空界面缓存，重开重新读取；运行状态变化也会使缓存失效，不能只用最近用户消息时间判断终态。旧格式需要迁移或状态暂不可读时显示在其他会话，不自动迁移或恢复执行。

`rtk proxy node scripts/harness.mjs attention-test --home .local/test-home` 在隔离 home 先关闭新投影，生成真实完成、用户停止和失败历史，再重启加载新投影，验证分类、无模型读取、无冷 Agent 激活和历史不变。需要本机配置的 proxy key。

### 旁问

`/btw 问题` 或 Windows 默认快捷键 **Ctrl+Alt+Shift+B** 打开独立旁问；快捷键复用现有旁问弹窗，不占用主输入框草稿。在并排会话中跟随当前输入焦点，其他弹窗打开时不抢键。选中的对话文字可以作为引用。快捷键可在原生设置中修改；保留宿主的 Ctrl+Alt+B 侧栏命令。

旁问继承主会话已完成回合，正在执行的回合不作为完整背景。它不停止主任务，问题和答复保存在独立旁问记录，不自动追加到主模型上下文。需要让主任务采用旁问内容时，显式使用“加入对话”；需要工具执行时，使用 `/btw-task 任务内容` 创建后台任务。`/btw-history` 查看当前会话最近 20 对旁问，记录留在本机，不随 Git 迁移。

`rtk proxy node scripts/harness.mjs btw-test --home .local/test-home` 使用隔离 home 和真实代理检查上下文继承、执行中的主回合未被取消、恢复后的实际读工具、旁问不进入主模型请求、零工具请求和重启续问。运行需要本机 `OPENAI_API_KEY`；不要使用日常 home。

`rtk proxy node scripts/harness.mjs lifecycle-test --home .local/test-home` 在隔离 home 验证消息回合边界、终态回报去重、工具输出隔离、停止/归档、重启、用户恢复、只读权限及脱离保留历史。最终原生/实际代理运行通过，41 秒；为稳定复现竞争，部分请求由原生请求钩子暂停，不声称这些暂停请求经过了代理。

实际前端归档合成父会话后，两条工作树子会话仍可找到并打开已完成历史。跨 worktree 子会话在展开的主会话下面显示，点击或 Tab 后 Enter/空格打开真实原生会话；行旁菜单直接复用原生置顶、重命名、分叉、归档及复制 ID。显示层不改 Workspace 归属、cwd 或历史。父会话归档、置顶或其工作区未呈现时，子会话恢复自己的原生列表位置；取消归档并展开父组后恢复嵌套。

单测覆盖父子/兄弟关系、独立 fresh/fork、脱离保留历史、跨家族拒绝、严格请求校验、停止与消息竞争、清空排队任务、归档保护、完成回传去重和树循环保护。

原有隔离 runtime 的 create/fork/read/send/stop/detach、重启持久化及已认证 RPC 测试证明底层接口，但不足以证明自动协作体验。本次另外通过真实 proxy 的 /collaborate 完整验收：Agent 自行查询目录、选择数量和模型、创建子会话、等候实际结果并完成汇总；请求头与全局默认模型、权限继承分别校验。没有把手工创建 RPC 或仅有工具列表算作自动验收。

原工作区会话列表按父子关系缩进，父行箭头折叠或展开子会话。关系来自同一服务，没有改写标题或会话事件；原生行的点击、菜单和归档保留。不同目录的子行是导航别名；自有行只接管 Enter/空格，不另造原生键盘选择系统。显示适配通过原生“展开其余会话”避免已呈现家族被五行水位线拆散，再使用父行箭头折叠家族。已归档或置顶项沿用原生位置；不会强行展开关闭的工作区，搜索结果继续保持搜索列表。

原生 0.2.1-rc.2 没有会话行重排槽位，因此显示适配集中在 `installSidebarTree`，只使用 `data-row-key` 标记和 ARIA；不依赖 CSS 哈希、不移动 React 所属节点。CSS 顺序配合 ARIA group ownership 呈现层级，卸载时恢复布局和属性。升级宿主需要重新验收。进度面板仍用于模型、状态与结果管理。没有移植 Claude 云端跨机器调度或完整团队审批协议。按需模式不会保证每个小任务都创建子会话；Agent 可能为多个子任务选择同一模型，效果与耗时仍取决于模型和 proxy。

`clean`/Git revert 后安装会卸载这项增强，但保留原生会话及插件 domain 数据；重新安装增强可恢复树。新电脑只获得程序与配置，不会拉取原电脑的会话、家族关系或记忆。

明确要求“先写 spec，再自动实现和验收”时使用 [自然语言交付流程](OPENSPEC.md)：主会话写规格并调度，standard 子会话实现，fresh reviewer 独立审查，主会话运行实际验收并维护任务状态。`start_session` 可指定 `agent_preset`，fresh 模式支持 standard/explore/planner/reviewer/cc；fork 继续保持源角色，不允许同时覆盖角色。

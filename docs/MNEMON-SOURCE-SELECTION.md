# Mnemon 记忆来源选择

`memoryView.entries["include:mnemon-strategy-scoped"].config` 的两种值不能混同：

- `{}`：交给范围组合选择适用来源（热记忆、档案、记忆空间）。
- `{"sourceKeys":[]}`：明确不选择任何来源，对应 View 没有这些来源的读写路由。
- `{"writableSourceKeys":[]}`：保留来源读取，但不授予写入。这是真正的只读配置，不能为修复另一项而清除。

GUI 的管理查询与 Agent 的 View 路由是不同路径；管理页能显示数据库，不能证明当前回合获准读取或写入。`mnemon_memory_bodies` 的目录查询可返回 `not-probed`，表示该查询没有等待健康检查，不能单凭它推断 Provider 已卡死。

## 设置页修复

0.5.40 上游界面把未设置的来源画成未勾选，与显式空列表外观相同。单纯保存其他字段不会自动写入空列表；勾选后再取消全部则会保存 `[]`，容易误以为恢复了默认。本仓库只补前端：默认来源显示实际适用项，保存显式零来源需确认；取消不提交，恢复默认仍省略字段，已有只读限制不变。没有修改数据库、View 校验或后端写入权限。

已误设为空时，在“记忆系统 → 配置 → 范围组合”对“参与 Source”点击“恢复默认”，再“应用”。随后用新回合/新会话检查正式记忆工具。不要通过直接写库、伪造 ActionOffer 或放宽权限绕过拒绝。安装器不自动覆盖其他用户明确设置的空范围。

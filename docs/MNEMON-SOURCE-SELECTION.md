# Mnemon 记忆来源选择

`memoryView.entries["include:mnemon-strategy-scoped"].config` 的两种值不能混同：

- `{}`：交给范围组合选择适用来源（热记忆、档案、记忆空间）。
- `{"sourceKeys":[]}`：明确不选择任何来源，对应 View 没有这些来源的读写路由。
- `{"writableSourceKeys":[]}`：保留来源读取，但不授予写入。这是真正的只读配置，不能为修复另一项而清除。

GUI 的管理查询与 Agent 的 View 路由是不同路径；管理页能显示数据库，不能证明当前回合获准读取或写入。`mnemon_memory_bodies` 的目录查询可返回 `not-probed`，表示该查询没有等待健康检查，不能单凭它推断 Provider 已卡死。

## 上游设置页与已移除的补丁

2026-11-06 按维护策略移除本地前端补丁，直接使用上游界面；不改动现有来源选择、记忆数据或读写授权。此举不代表上游缺陷已经修复。

0.5.40 上游界面把未设置的来源画成未勾选，与显式空列表外观相同。单纯保存其他字段不会自动写入空列表；勾选后再取消全部则会保存 `[]`。不要把取消全部勾选当作恢复默认。

已误设为空时，在“记忆系统 → 配置 → 范围组合”对“参与 Source”点击“恢复默认”，再“应用”。随后用新回合/新会话检查正式记忆工具。不要通过直接写库、伪造 ActionOffer 或放宽权限绕过拒绝。安装器不自动覆盖其他用户明确设置的空范围。

## 验证

`scripts/test-mnemon-view.cjs` 在对应 Electron Node 宿主运行，要求隔离 `DSH_HOME`、匹配的 `DSH_NATIVE_ROOT`，并使用原生工具。脚本设置独立 meme 目录、禁用外部 Orca Hook。`empty` 模式复现空范围拒绝；`readonly` 模式检查允许读而拒绝写；默认模式建立测试空间，经 Standard/PTC 新会话写入和召回合成内容。原生记忆维护会调用模型，须显式提供隔离测试所需的模型路由和环境凭据；不把这项当成无模型测试，也不对生产 home 运行。

测试内容和失败日志留在隔离目录；不提交真实记忆、凭据或个人路径。

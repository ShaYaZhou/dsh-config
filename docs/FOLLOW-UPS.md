# 后续任务与输入建议

主任务处理完后，Agent 可提出最多三项可选后续任务及一条输入建议。提议只保存元数据，不执行任务。可以自然语言要求“给出可选后续任务，等我确认后再开始”。

- **独立启动 / 全部启动**：确认后预检并固定本地已提交基线，使用原生 Git worktree 和独立会话。多仓库环境逐仓库隔离；未提交改动不会自动复制。原任务继续。
- **在这里执行**：作为明确用户消息排入当前会话，不替换未发送草稿，每次一项。
- **查看会话**：打开真实原生会话；结果沿用现有有界回报。
- **输入建议**：空白、无附件/引用/排队消息且回合结束时显示。Tab/右方向键采纳为草稿，Enter 不发送尚未采纳的建议，Esc 隐藏。设置 → 后续建议可关闭，重启和部署保留偏好。

建议复用本回合输出，不另发后台推理请求，与[官方桌面文档](https://code.claude.com/docs/en/desktop#accept-a-suggested-prompt)的后台生成方式不同；对齐操作契约，不声称私有实现相同。独立启动/当前会话执行/全部启动来自用户提供的公开报道及[公开分享](https://timeline.sohu.com/news/fAtXLhSiR3)，不能断言当前官方各版本的按钮文案。

## 职责与保护

`plugins/follow-ups` 拥有提议、确认及显示；Git 准备复用公开 `local-environments/workspace` helper，派发复用 trusted `nestedSessions.sendWithSignal`。后者不注册为 Remote，原 send 远程参数不变。UI 调 owner RPC；模型仅有 `propose_followups`，不能确认或改用户偏好。只在根会话提议，子会话向根请求更多分工。

提议/admission 使用原生 `appendPluginRecord` 可忽略记录及 projection，偏好使用独立原生 storage domain。先记录保留身份再执行；失败或重启后结果不确定时保留线索，不自动重试。新用户任务、停止、目录或权限/Agent 配置变化撤销未派发建议；取消信号跨调度队列及目标解析，在最终 enqueue 前再次检查。

## 验收与范围

`rtk proxy node scripts/harness.mjs follow-ups-test --home <隔离且已安装的-home>` 需要既有 proxy key。最终原生/代理运行 63 秒通过：真实提议、确认前无执行、原任务继续、两个独立 worktree 实际写入、重复确认去重、当前会话用户队列、权限继承、冷读/关闭无 Agent 激活或额外推理，偏好跨宿主重启，以及卸载插件后原生冷读历史逐事件不变。

原生前端实际点击验证了任务卡片、全部启动、打开/返回会话及草稿保留；Enter 不发送，Tab/右方向键仅采纳且模型请求数仍为 2；设置关闭写入持久偏好。IME/菜单/隐藏面板/非空草稿/附件/引用/排队消息、迟到响应及取消/权限变化有独立回归。全套及隔离源码副本均为 115 项通过，无跳过。

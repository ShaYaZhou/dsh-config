# 并行写入与整合

使用已有原生 `create_worktree`、`working_directory` 和 linked-session 工具，不另建 Git 调度器。研究任务可只读共享目录；并行写代码先隔离 checkout，主会话负责审阅和整合，再运行交付工作区的验收。

可直接对主会话说：

> 并行修复这两个独立模块。为写入者准备独立 worktree，保留我的未提交修改。只带入我指定的 fixture.config.json，不复制其他忽略文件。收集结果后检查 diff，整合回当前工作区并运行验收。

主会话先检查仓库、原工作目录和固定基准 commit。`create_worktree` 会切换**调用会话**的目录；连续准备多个 checkout 时，每次回到原目录再创建下一个，分派前也回到原目录。将实际返回的绝对 cwd 传给子会话；这些运行路径留在本机，不写入可迁移配置模板。

原生工具从 commit 创建新分支，不复制源目录的未提交内容、忽略文件或凭据，也不自动安装依赖。需要本机配置时，只按用户明确选中的文件和项目已有初始化方式带入；不扫描并搬运全部 `.env` 或隐藏文件。工作目录切换不扩大原有文件权限。

每个写入者只改自己的文件。允许本地 commit 的任务可让子会话提交并回报 SHA，主会话先审阅 commit，再串行 cherry-pick；没有提交授权时保留改动，由主会话按原项目流程审阅转移。冲突应停留在可见的整合步骤处理，不能用 reset/clean 丢弃原有工作来取得通过。

整合后才做最终验收。需要撤销已提交的整合结果时，可对整合 commit 使用 `git revert`；这与配置仓库安装器的 `rollback` 是不同层面的恢复。未合并的分支、工作目录和会话历史保留，便于审阅和恢复，不自动递归删除。

## 维护者验收

```powershell
rtk proxy node scripts/harness.mjs worktree-test --home <已安装的隔离测试目录>
```

需要本地代理 key，会产生真实模型请求。命令拒绝生产 home，和其他代理 runner 共用 home lease，结果单独写 `.local/worktree-delivery-test/`。它创建自己的合成仓库，测试两个独立修复、原生 worktree、实际并发、选择性配置带入、主会话整合、保留原验收和未提交笔记，以及仅在该合成仓库执行的 revert。失败保留目录、分支和会话，不把结构检查或启动成功当作通过。

`DSH_WORKTREE_VERIFY_LAST=1` 只恢复上次合成任务的**回滚前验收**，不再次请求模型实现。恢复指针在启动失败时保留，成功写入结果后才删除。首次 revert 前写入回滚记录；进入回滚后拒绝从头重放验收，可查看保留的测试目录或不带该环境变量创建全新 fixture。这里不实现 Git sequencer 的自动修复，也不影响真实产品会话的恢复功能。

源码归因比较保留实际文本内容，只统一 CRLF/LF；原验收、项目指令和源目录未提交笔记仍按原始字节检查。完成数量使用实际 writer 及其持久回合时间；每份真实提交补丁须返回主会话，整合提交须对应已完成 writer 的补丁，不凭命令出现某个单词认定成功。

这项验收不覆盖所有 Git 冲突、submodule、LFS、仓库钩子、依赖安装和项目专用生成流程；这些仍应按实际项目规则处理。

# 日常精简 PTC 与按需增强

常规 `scripts/harness.mjs install` 部署两个桌面能力集合：

| Profile | 用途 | 默认加载 |
|---|---|---|
| `desktop` | 桌面应用日常入口，默认原生 PTC | 官方 base/web-app，原生预设与权限/取消/持久化，独立浏览器、按需嵌套会话、内联动态卡片、插件市场及 Harness增强管理入口 |
| `enhanced` | 明确需要完整增强、旧 Workflow 停止/恢复时 | 原有协作、工作流、记忆、技能和界面增强 |

`headless` 使用原生无头配置。部署不迁移、重写或删除会话、记忆、工作流日志和浏览器登录资料；安装器先备份管理文件，原有 `rollback` 继续可用。

## 日常使用

完全退出并重开桌面应用，新会话默认选 PTC。Standard 仍是原生可选项。日常 profile 默认不加载本地 Ultracode、自动记忆、Team、整套额外技能库；保留嵌套会话及其控件；项目规则及原生技能发现机制保持原生行为。个人全局技能目录不被修改或删除。

插件市场与「设置 → Harness增强」属于管理入口，日常配置保留。六项功能（Team、worktree 工具、浏览器与桌面指引、会话总线、Claude 上下文、用量报告）的条目和源码已经安装，默认 disabled，通过原生插件管理器按需开启或关闭。Team 依赖的被动 worktree 服务常驻，但不自动暴露 create_worktree 工具。指引只提供提示与技能，不安装桌面控制驱动。部署会恢复模板的默认关闭状态。

打开管理页不会启用执行插件；确实未安装的功能仍明确标注并禁用开关，包括日常配置未安装策略时的 Ultracode 设置。完整增强能力仍需下述 enhanced profile。

## 按需使用完整增强

从匹配版本的 CLI 显式启动：

```sh
dsh --profile enhanced
```

这是同一 DSH_HOME 下的独立 profile。不要同时在两个入口执行同一历史会话。旧 Workflow 的 `/workflow resume`、停止锁和日志继续由 enhanced 中的原有实现解释；不要在日常模式把失败/停止的任务重新描述为“继续执行”以绕过恢复判断。默认入口没有伪造同名增强命令。

仓库 `config/desktop.*` 保留完整增强来源；`presets/daily/` 与安装器的 `renderDailyPlan` 负责精简入口。受管技能只部署到 `profiles/enhanced/agent-capabilities/skills/`，不会在日常模型上下文列出整套额外技能。

## 浏览器隔离与停止

两个 profile 都使用原生 MCP 的代理作用域：每个执行者有独立连接、临时浏览器上下文和独立输出目录。子代理不会继承父浏览器的页面、cookies 或截图目标；要复核页面，应重新导航到同一预览地址，而不是假设共享标签。

此方案解决不同执行者共享页面状态的冲突，不限制无关任务并行，也不新增任务调度器。单个执行者内部依赖页面状态的操作仍应顺序执行。自定义文件导出路径、服务端 unsafe 代码和权限升级被拒绝。

正常完成后的同一会话可复验；普通 Agent 释放仅清理连接，不等于明确停止，重新唤起时可建立新连接并重新导航同一产物。旧 Agent 的迟到清理不会关闭新实例。

停止、错误、中断回合会关闭该执行者的浏览器连接；不自动重启或重放不确定操作。需要重新浏览时新建会话，其他执行者的独立浏览器保持可用。代理卸载和应用退出复用原生生命周期清理。明确停止或清理失败会锁住该 owner 的通用执行和新增委派入口（包括 shell、PTC），只保留有限只读工具，防止改用进程启动浏览器；该锁使用原生可忽略插件记录持久化。正常成功且未释放的回合可继续使用自己的页面。

隔离浏览器不替代文件沙箱，也不阻止两个写入者通过文件或外部数据库产生冲突；并行实现仍需要独立 worktree 或明确的唯一写入者。

## 验证与回滚

- `npm test`、`node --test test/portable.test.mjs`。
- `scripts/test-daily-browser.cjs`：隔离 DSH_HOME 中真实模型驱动 Standard/PTC 导航、页面互不污染、导出拒绝、停止释放；需要已配置模型凭据，不复制凭据文件。
- 再用原生 persistence 冷读测试历史，不能只以工具返回成功判定验收。
- `scripts/test-preset-loading.cjs` 可在 enhanced profile 验证旧增强服务；Workflow 恢复单测继续运行。
- 安装先 dry-run，部署后 status；回滚只恢复受管文件，不删除会话与测试证据。

六组网页实验支持“精简默认”的方向，不证明所有可选增强无价值，也不保证每个任务一定提速。此次保留完整增强供明确任务使用。

## 嵌套会话开关

输入框模型选择器左侧的“嵌套会话”提供 auto / on / off，新任务默认 auto，界面调用既有 `/collaborate` 命令：

- auto：按任务需要选择普通子代理、Team（若配置已启用）或持久关联会话。
- on：简单工作仍可直接做；新增独立分工通过关联会话执行，已有 Workflow 继续负责其执行。拒绝同时从 Team/subagent 工具另派相同工作。
- off：禁止新增关联会话，允许普通子代理与 Team；不会停止已有任务。

已有 Team 任务的通信、结果收取及复验保留；关联执行者需要更多分工时向原协调者请求，不另建 Team 或孙会话。界面名改为“嵌套会话”，`/collaborate` 命令及已有存储语义不变。

## 内联动态卡片

日常保留 render_widget 工具及一份受管 dynamic-ui 技能，技能正文通过原生 skill 工具按需读取，不把整套技能库注入每轮。输入 /dynamic-ui 使用原生技能入口，或直接要求“在对话中画交互卡片”。它用于紧凑图解、对比和单控件演示；完整网页、应用和长看板仍交付文件，不强制转卡片，也不要求启动浏览器。片段继续在不同源iframe中运行，保留现有CSP和尺寸限制。

本机在模型设置中增加的其他接入可在忽略的本机settings文件中通过 additionalProviders 保存（仅提供商定义和apiKeyEnv引用，不允许apiKey字面值），配合 defaultProvider/defaultModel 生成到运行配置；reasoningEffort为null时保留原生自动选择。不要把带凭据的整份配置导出到仓库。
